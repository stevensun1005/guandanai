# 电脑对手：输入、决策与验证

## 当前默认引擎

默认电脑使用强化学习价值网络。控制器先生成合法候选动作，后台 Worker 对候选动作评分，再将结果作为普通出牌事件提交。

普通界面不会展示模型名称、耗时或模式开关。玩家只需要对局；如果资源加载失败，会出现重试入口。

## 模型能看到什么

- 当前座位自己的手牌。
- 这局公开打出过的牌和过牌记录。
- 其他座位剩余的张数。
- 当前级牌与双方级数。

不会把其他座位各自的隐藏手牌传给模型。房主浏览器维护完整对局状态，这不等于模型使用了这些隐藏信息。

## 推理路径

`ai/controller.js` → 合法候选 → `ai/encoding.mjs` → `ai/worker.mjs` → ONNX 模型 → 合法性校验 → 对局事件。

模型局面特征为 513 维，动作特征为 54 维。浏览器模型把二者作为独立输入，每批共享局面计算，避免为每个候选动作重复复制同一局面。

进贡和还贡是独立的规则阶段，使用专门的合法选牌逻辑，不把它们伪装成模型出牌决策。

## 风格与独立模型

两者需要分清：

- **出牌风格**：在同一个引擎上调整风险偏好、牌型保留和配合方式。
- **独立模型**：不同的网络或权重文件，必须有真实可加载的模型资源及单独验证。

目前提供四种风格，共用经过数值验证的强化学习权重：

| 风格 | 当前行为                                         |
| ---- | ------------------------------------------------ |
| 均衡 | 保持模型原有的最高分选择，综合处理不同局势       |
| 激进 | 在评分接近时更愿意争先、出多张牌和动用炸弹       |
| 稳健 | 在评分接近时保留炸弹、百搭和控制牌，关注队友领先 |
| 观察 | 结合本局公开回应频率、对手报牌和队友领先调整选择 |

风格只在与最佳模型评分相差不超过 0.055 的候选中选择。它不是随机出牌，也不代表不同风格都更强。过牌被当作一次选择记录，不会据此断言对方没有某种牌。观察记录按本局统计，尚未建立跨局的人物画像。

大厅按东南西北设置，开局转换为房主座位编号。加入的朋友只查看设置；电脑接管空位时沿用该座位配置。联机转为本机继续时同步旋转座位映射。

## 开发者评估

```bash
python -m pip install numpy onnxruntime
npm run eval:profiles -- --pairs=600 --seed=20261104
```

工具以 Python 子进程进行本机 CPU 推理，使用固定发牌和相同先手，交换受测双方；它不属于网站，不会开启推理服务。结果写到 `work/validation/profiles`，包含胜率、配对升级分区间、与均衡的选择差异、过牌／炸弹变化和原始逐局结果。通过 `--seed` 留出未用于调整的牌局。

评估使用单局随机级牌，不包含跨局进还贡和整场打 A，因此不能把结果直接当作完整比赛胜率。生产网页仍完全在浏览器推理，不依赖 Python。

## 判断改进是否有效

使用固定发牌、交换双方、留出未参与调整的牌局。除胜率外，还记录升级分、出牌合法性、计算耗时和选择差异。

单次漂亮出牌不代表整体更强。没有稳定验证结果的候选策略不会替换默认引擎。性能优化与棋力提升也分别记录。
