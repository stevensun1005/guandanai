# 电脑对手：输入、决策与验证

## 当前默认引擎

默认电脑使用强化学习价值网络。控制器先生成合法候选动作，后台 Worker 对候选动作评分；可唯一还原的两家小残局会额外进行精确校验，最后仍作为普通出牌事件提交。

普通界面不会展示模型名称、耗时或模式开关。玩家只需要对局；如果资源加载失败，会出现重试入口。

## 模型能看到什么

- 当前座位自己的手牌。
- 这局公开打出过的牌和过牌记录。
- 其他座位剩余的张数。
- 当前级牌与双方级数。

不会把其他座位各自的隐藏手牌传给模型。房主浏览器维护完整对局状态，这不等于模型使用了这些隐藏信息。

## 推理路径

`ai/controller.js` → 合法候选 → `ai/encoding.mjs` → `ai/worker.mjs` → ONNX 模型 → 合法性校验 → 对局事件。

模型局面特征为 513 维，动作特征为 54 维。浏览器模型把二者作为独立输入，每批共享局面计算，避免为每个候选动作重复复制同一局面。

进贡和还贡是独立的规则阶段，使用专门的合法选牌逻辑，不把它们伪装成模型出牌决策。

## 风格与独立模型

两者需要分清：

- **出牌风格**：在同一个引擎上调整风险偏好、牌型保留和配合方式。
- **独立模型**：不同的网络或权重文件，必须有真实可加载的模型资源及单独验证。

目前提供四种风格，共用经过数值验证的强化学习权重：

| 风格 | 当前行为                                         |
| ---- | ------------------------------------------------ |
| 均衡 | 保持模型原有的最高分选择，综合处理不同局势       |
| 激进 | 在评分接近时更愿意争先、出多张牌和动用炸弹       |
| 稳健 | 在评分接近时保留炸弹、百搭和控制牌，关注队友领先 |
| 观察 | 结合本局公开回应频率、对手报牌和队友领先调整选择 |

风格只在与最佳模型评分相差不超过 0.055 的候选中选择。它不是随机出牌，也不代表不同风格都更强。过牌被当作一次选择记录，不会据此断言对方没有某种牌。观察记录按本局统计，尚未建立跨局的人物画像。

## 公开信息残局

当只剩两个不同队伍的玩家、总手牌不超过 16 张时，两位已出完者的全部牌都已经公开。用完整牌库减去自己的牌和公开出牌，恰好就是唯一剩下的对手手牌；这里不需要读取另一家的隐藏状态。

`ai/endgame.js` 用这些牌做精确的对抗搜索，处理过牌后的重新领出与已走完玩家的接风。它优先检查模型评分高的动作，只在证明某条路线能先走完时采用；如果不能证明、牌数不一致或预算用完，就继续使用学习策略。四种风格都遵守这条已证明路线。

节点预算为 40,000，时间预算约 80 ms，计算发生在 Web Worker，不在界面线程。这项改进针对最后两家的收尾与升级分：到这一阶段，头游所属队伍已经确定，因此不以胜率上涨作为目标。它没有修改或重新训练神经网络权重。

大厅按东南西北设置，开局转换为房主座位编号。加入的朋友只查看设置；电脑接管空位时沿用该座位配置。联机转为本机继续时同步旋转座位映射。

## 开发者评估

```bash
python -m pip install numpy onnxruntime
npm run eval:profiles -- --pairs=600 --seed=20261104
```

工具以 Python 子进程进行本机 CPU 推理，使用固定发牌和相同先手，交换受测双方；它不属于网站，不会开启推理服务。结果写到 `work/validation/profiles`，包含胜率、配对升级分区间、与均衡的选择差异、过牌／炸弹变化和原始逐局结果。通过 `--seed` 留出未用于调整的牌局。

残局增强可以单独比较：`npm run eval:profiles -- --styles=endgame --pairs=2000 --seed=20263104`。基线为未开启精确残局的均衡策略。

### v1.4.0 留出检查

未用于开发检查的种子从 `20263104` 开始，2,000 组交换双方，共 4,000 局。相对原均衡策略，配对升级分合计改善 **152 分**；152 组改善，0 组下降，其余一致。每组两局的平均改善为 **0.076 分**，95% 区间为 **[0.0644, 0.0876]**。双方胜局仍为各 2,000 局，符合这项功能只介入头游已经确定之后的设计。

结果与限制：只覆盖这些固定发牌的独立单局，不是整场打 A 的成绩；搜索预算和设备性能也会影响介入次数。数据见 [残局结果 JSON](evaluation/endgame-1.4.0.json)。浏览器额外复现了 8 个实际记录的改选残局，并检查风格不会覆盖证明结果。

评估使用单局随机级牌，不包含跨局进还贡和整场打 A，因此不能把结果直接当作完整比赛胜率。生产网页仍完全在浏览器推理，不依赖 Python。

### v1.3.0 行为检查

固定种子 `20261104`，每种风格 600 组交换双方的发牌，共 3,600 局。数据见 [结果 JSON](evaluation/profiles-1.3.0.json)。

| 风格 | 对均衡胜率 | 选择改变率 | 同一局面下的行为变化                 |
| ---- | ---------: | ---------: | ------------------------------------ |
| 激进 |     51.00% |      2.78% | 少过 730 次，多用炸弹 508 次         |
| 稳健 |     50.08% |      2.33% | 多过 626 次，少用炸弹 399 次         |
| 观察 |     50.25% |      0.93% | 结合公开回应，在较少的局面中调整选择 |

这些结果支持“行为有差异”，尚不足以支持“风格比均衡更强”：三种风格的配对升级分 95% 区间都包含零。因此均衡仍为默认，风格供玩家按偏好选择。

## 判断改进是否有效

使用固定发牌、交换双方、留出未参与调整的牌局。除胜率外，还记录升级分、出牌合法性、计算耗时和选择差异。

单次漂亮出牌不代表整体更强。没有稳定验证结果的候选策略不会替换默认引擎。性能优化与棋力提升也分别记录。
