# GuandanAI：面向整场团队胜利的浏览器掼蛋智能体

**持续更新技术报告 · 版本 1 · 2026-11-04**

本文描述仓库中可以检查的实现和实验，不是同行评审论文。正文区分已部署系统、历史实验、正在训练的候选及待验证假设。训练进展由第 11 节及配套 JSON 持续记录；实验代码、统计口径或权重变化时，正文也必须更新。

## 摘要

GuandanAI 是四人两队的浏览器掼蛋系统。当前默认电脑使用一个共享的多层感知器价值网络，观察型与融合型额外使用监督训练的应牌预测网络。五种性格并不对应五套独立训练的神经网络；当前系统也没有接入大语言模型。风格偏好、公开习惯统计和有限的确定性残局搜索属于网络之外的决策组件。

研究目标是提高从打 2 到通过 A 的**整场队伍胜率**，同时保留升级、队友名次、进还贡和打 A 失败次数的跨局影响。实验包括冻结提案网络上的裁剪 PPO，以及对约 137 万参数价值网络的分阶段解冻与终局蒙特卡洛回报回归。后者使用全部已生成的合法候选，以三路同步采样收集自对弈、历史模型对抗和规则对抗数据。

目前证据支持三个有限结论：应牌网络在固定教师分布上的预测误差低于线性基线；历史小策略头在独立**单把**测试中取得 2.53 个百分点的胜率提升；扩大公开确定性残局搜索范围在特定历史配置中提高了平均升级分。当前还没有新的独立整场验收证明达到 80% 胜率，也没有证据证明全网络候选应替换网页默认权重。开发集峰值、参数更新和较低训练损失均不等同于已验证的整场棋力提升。

## 2. 游戏环境、观察和动作

### 2.1 团队目标

四席按相对座位奇偶分成两队，同队共享最终整场回报。头游所在队取得当前单把的升级资格，但队友名次会改变升级幅度和下一把进贡关系，因此头游不是整场终止条件。整场训练使用网页的同一份[比赛结算模块](../src/core/match.js)。默认实验含进贡、抗贡和还贡；三次打 A 未过按实验桌规判平局。

以终局时本队的结果定义回报：

$$
R = \begin{cases}
+1,&\text{本队赢得整场},\\
-1,&\text{本队输掉整场},\\
0,&\text{按桌规平局}.
\end{cases}
$$

整场结束后，同队两席的已记录动作收到相同符号的回报。头游之后仍记录队友和剩余玩家的决策。双上、双下和孤立头游作为分析统计记录，没有额外变成“必须送队友”或“弱牌不能炸”的硬性禁令，也未作为当前全网络训练的手工战术奖励。

### 2.2 信息边界

用 $o_t$ 表示当前座位可获得的观察，而不是包含四家真实私牌的完整状态。策略输入来自本人的手牌、公开出牌、各席剩余张数、级牌及公开整场进度。未见牌向量表示“全副牌减去自己的牌和公开已出牌”的合计数量，不给出这些牌分别属于哪家。

房主浏览器持有整桌状态以执行游戏规则，但[模型观察构造](../src/ai/observation.js)只向当前座位发送上述信息。规则基线的适配器同样隐藏其他人的牌对象，仅保留公开张数。明牌练习展示四家牌，也不因此给策略网络额外输入队友或对手的私牌。

这些边界由代码与测试检查；本文没有据此宣称信息安全已经经过独立审计。公开的过牌是行为观察，不是“没有能跟的牌”的确定证明。

### 2.3 牌与动作编码

两副牌的 108 个实体 ID 在模型中归并为 54 种“点数与花色”位置，每种最多两张。**花色保留**，不能把此编码描述成忽略花色。同点数不同花色在同花顺和百搭处理上仍可区分。历史中的缺席或过牌还使用专门的零向量／负值哨兵，所以整个观察向量并非只含 0、1、2。

513 维主观察包括七组 54 维牌向量（本人、未见牌、最近出牌、队友最近出牌以及其他三席累计已出牌）、12 个百搭相关标志、三组 28 维余牌数独热向量和三组 13 维级数独热向量。候选动作再提供 54 维牌计数，组成 567 维输入。具体排列以[编码实现](../src/ai/encoding.mjs)和数值一致性测试为准。

合法动作由[候选生成器](../src/ai/candidates.js)提供，包括允许时的过牌。完整网络实验对**生成器提供的全部合法候选**评分；这不等于本文已对 27 张大手牌的所有实体组合做了形式化穷尽证明。重复实体牌可能产生相同编码的动作，均匀候选探索也不等于对所有语义牌型均匀探索。

## 3. 已部署系统：两个网络与五种性格

### 3.1 网络结构与身份

| 编号 | 网络           | 结构                                                                |  参数数量 | 当前用途               |
| ---- | -------------- | ------------------------------------------------------------------- | --------: | ---------------------- |
| P0   | 主动作价值网络 | $567\to512\to512\to512\to512\to512\to1$；五个 tanh 隐藏层、线性输出 | 1,341,953 | 五种性格共享           |
| R1   | 应牌预测网络   | $253\to64\to32\to1$；两个 tanh 隐藏层、sigmoid 输出                 |    18,369 | 观察型、融合型按需调用 |

默认主网络在本阶段作为固定初始化权重使用。现有仓库没有提供它从随机参数开始预训练的完整数据和优化日志，本文不宣称重现了该预训练过程。后续实验哪些层实际更新，另外报告，不以“使用神经网络”替代训练证据。

### 3.2 五种性格的真实差别

| 性格 | 实际神经网络 | 网络外的差别                                             | 是否单独训练的 RL 模型         |
| ---- | ------------ | -------------------------------------------------------- | ------------------------------ |
| 均衡 | P0           | 通常选择最高价值分数；仍受结束手牌捷径和公开残局模块影响 | 否，共享 P0                    |
| 激进 | P0           | 在接近最高分的候选内加固定的节奏、争先偏好               | 否                             |
| 稳健 | P0           | 在接近最高分的候选内加固定的控制牌与炸弹保留偏好         | 否                             |
| 观察 | P0 + R1      | 公开过牌／回应统计与受限应牌预测排序                     | 否；R1 是独立监督模型          |
| 融合 | P0 + R1      | 用固定公式按局势混合前三类偏好                           | 否；混合权重不是另一个学习网络 |

当前[风格实现](../src/ai/profiles.js)只在价值分数距离最高分不超过 0.055 的候选中调整。0.055 是分数阈值，不是“胜率差 5.5%”。风格偏好包含手工系数，**不能描述成五个自行学会不同人格的智能体**。

观察与融合型保留当前单把及最近四把的公开习惯，历史把按 0.6 的幂衰减，并区分面对对手与让队友领出。它们更新的是[公开统计量](../src/ai/habits.js)，不在玩家浏览器中进行梯度下降；“适应了统计”不等于“在线训练了神经网络”。

R1 只在已经决定出牌、下一位仍在场的玩家是对手、且至少两种非过牌候选接近最高分时比较应牌风险。它不把当前的过牌决定改成出牌，也不把出牌改成过牌；预测对象是采样教师策略的行为，不能直接解释成任意真人的真实应牌概率。

### 3.3 网络外的决策组件

当前网页仍包含合法候选生成、可直接出完手牌时的捷径、风格排序和公开确定性残局求解。只有两家仍有牌、且另一家手牌能由本人手牌及公开出牌唯一重建时，才申请残局搜索。已发布配置上限为总计 24 张、40,000 节点、约 80 ms；预算不足时不输出已证明路线，交回常规网络／风格决策。已证明的残局路线优先于风格偏好。

这个模块是受预算限制的确定性搜索，不是神经网络，不是完整四人隐藏信息蒙特卡洛树搜索，也不证明此前整场比赛的最优性。它与主网络参数学习的贡献应分开评价。

## 4. 实验模型与优化目标

### 4.1 冻结提案上的小策略头

历史单把 PPO 使用冻结网络提取的 512 维表示和 53 维补充公开特征，Actor 与 Critic 分别为 $565\to64\to1$，共更新 72,578 个参数。整场版本再追加 8 维公开进度，变为两套 $573\to64\to1$，共更新 **73,602** 个参数。该数量不含被冻结的提案网络，不应误称为整个系统的总参数量。

整场补充信息是双方级数、双方打 A 失败次数、当前打哪方的级、截断归一化后的把数以及上一把本队／对手是否双上。动作仍被限制在冻结提案评分的前四个候选内，Actor 在这些候选上形成带掩码的分类分布。Critic 对候选特征的均值预测整场回报。整场版本在头游后继续使用 Actor，旧单把版本的结束阶段处理不同。

实际提案文件由每个检查点的 `proposalSHA256` 标识；整场实验使用过含早期残差修正的冻结提案，不能把所有 PPO 实验都说成完全相同的 P0。早期残差价值头与 PPO Actor 也不是同一种算法。

以记录的旧策略概率计算重要性比率 $r_t$，使用裁剪策略目标：

$$
L_{\mathrm{policy}}=-\mathbb E[\min(r_t A_t,\operatorname{clip}(r_t,1-\epsilon,1+\epsilon)A_t)],\qquad
A_t=R-V_{\mathrm{old}}(o_t).
$$

优势在整个缓冲区归一化，不在单场内部中心化。训练还含 Critic 均方误差、熵项和相对于冻结提案分布的 KL 约束。已记录默认配置为裁剪 0.2、学习率 $3\times10^{-4}$、4 个 epoch、batch 512；实际设置以训练报告为准。单把与整场使用的回报定义不同，不能混合报告胜率。

分布的 logits 为冻结提案分数除以温度 0.15，再加 Actor 修正值；Critic 损失权重为 0.5，熵权重及提案 KL 权重均为 0.01，旧策略 KL 超过 0.03 时可提前停止。历史单把实验的回报为胜负符号乘以 $(1+0.1\times\text{升级分})$，不是整场版本的 $+1/-1/0$。

### 4.2 完整价值网络的逐步解冻

全网络实验把输入扩为 $513+54+53+8=628$ 维，结构为 $628\to512\to512\to512\to512\to512\to1$，共 **1,373,185** 个参数。已有权重用于初始化，新增 61 维输入的投影初始为零；初始输出缩放为原主网的三分之一以匹配回报尺度，保持初始动作排序。这不是从随机权重重新训练全部能力。

| 训练阶段 | 放开的部分                           | 本阶段可训练参数 |
| -------- | ------------------------------------ | ---------------: |
| 后层     | 最后一个隐藏层、输出层和新增信息投影 |          294,401 |
| 中后层   | 后三个隐藏层、输出层和新增信息投影   |          819,713 |
| 全网     | 原输入层至输出层及新增投影           |        1,373,185 |

每条被选择的动作保存原始观察与动作特征，终局回填团队回报；按完整比赛划分训练与验证，避免同场动作同时进入两边。训练拟合：

$$
L(\theta)=\mathbb E[(Q_\theta(o_t,a_t)-R)^2]
+\lambda\mathbb E[(Q_\theta(o_t,a_t)-Q_{\theta_0}(o_t,a_t))^2].
$$

第二项保持初始化网络在采样动作上的输出知识，不限制合法出法。当前受保护试验使用 $\lambda=50$、AdamW、学习率 $10^{-6}$、batch 256、每周期 2 个 epoch；最初较大步幅实验没有这一约束并出现严重实战退步。这项约束没有对所有未选动作建立策略 KL 保证，仍可能改变动作排序。

每次更新比较验证均方误差并保存较好的检查点，同时保留最后一次实际优化状态。因此必须区分“某层参与反向传播”“优化器确实改变了参数”“改变后的参数被选中”和“对战更强”四件事。均方误差下降不构成后两项的证明。

每条决策在损失中按样本计权，较长比赛或决策较多的席位贡献更多训练项；当前没有保证每场比赛等权。这是实现约束，不应省略。

### 4.3 采样与对手池

全网络每周期计划 192 场完整比赛，三路本地采样进程各 64 场，全部采样完成后再更新共享权重。这是单机同步采样／学习流程，不是异步分布式 GPU 集群。每次决策以 0.05 概率从生成的全部候选中随机探索，否则贪心；评测使用贪心选择。

采样轮换四席当前模型自对弈、冻结历史版本以及项目现有规则机器人。自对弈中四席各自只观察自己的牌；对历史／规则对抗时只训练本队两席。规则对手保留原有理牌、记牌与协作实现，不是随机机器人。进还贡沿用游戏环境的现有程序，本阶段没有把贡牌选择也改为可学习策略。

自对弈中两队共用同一模型，因此自身对抗的胜率不用于证明绝对棋力。定期评测分别对规则与冻结历史模型；开发集上对规则胜率提高、且对历史不下降，才把候选保留为后续训练起点。这是开发筛选，不是发布验收。

### 4.4 新实验：公开出牌网络、明牌评价与开局重打

本轮新增四组对照，均从同一初始化出牌网络开始，并使用相同的完整网络 PPO 优化设置：

这里的“公开／暗牌”简写指出牌者的合法信息，包含本人的手牌与公开记录；“明牌评价”才额外包含其他三席的当前手牌。

| 组别 | 出牌网络可见信息   | 训练评价网络 | 开局题目       |
| ---- | ------------------ | ------------ | -------------- |
| A    | 本人手牌与公开信息 | 公开信息     | 全新           |
| B    | 本人手牌与公开信息 | 公开信息     | 全新＋难题重打 |
| C    | 本人手牌与公开信息 | 当前四家牌   | 全新           |
| D    | 本人手牌与公开信息 | 当前四家牌   | 全新＋难题重打 |

出牌 Actor 为完整的 1,373,185 参数网络，所有层参与优化。评价 Critic 是单独的 $683\to256\to128\to1$ tanh MLP，共 208,129 参数。683 维由 513 维公开出牌观察、8 维公开整场进度及其他三席各 54 维当前手牌组成。A／B 保持相同 Critic 结构，但后 162 维填零；C／D 才使用真实当前手牌，以匹配网络容量。

Actor 的采样分布来自全部候选分数除以温度 0.03 后的 softmax。只有 Critic 接收另一个 `criticOnly` 参数，Actor 输入构造不读取私牌列。部署导出只需要公开 Actor；Critic 不加入网页模型清单。当前实现通过状态价值基线辅助策略梯度，没有训练一个明牌最优出牌教师，也不把某次明牌动作硬编码成学生答案。

四组使用 Adam：Actor 学习率 $10^{-6}$，Critic 学习率 $3\times10^{-4}$，每周期 2 个 epoch，batch 8 个决策，PPO 裁剪 0.1，Critic 损失权重 0.5、熵权重 0.001、初始化策略 KL 权重 0.05。相对旧策略的批次 KL 超过 0.02 时提前停止；Actor 与 Critic 分别裁剪梯度范数到 1。优势使用已存储的旧 Critic 值，按缓冲区归一化。目标仍为整场 $+1/-1/0$，没有额外战术奖励。

重打只固定第一把的发牌种子、本队阵营及对手模式；后续发牌序列、动作探索随机数重新生成。难题从该组此前训练对局的失利或平局中筛选，排除四席共用同一模型的自对弈结果。每周期最多一半场次重打，其余使用新开局；无难题则全用新题。候选历史池上限 1,000 项，不代表已经完成 1,000 副训练。整场失利也不能证明该开局某一步一定有错，这只是采样课程的筛选信号。

同一开局及其重打版本只进入训练，开发评测使用另外的种子，最终留出再独立预留。输入不包含种子，明牌评价不提前读取未来尚未发出的牌。这是在预算内改进策略，不是声称求出完整四人掼蛋的最优解。

流程检查已完成四组各 12 场、共 48 场。四组第一批轨迹 SHA-256 完全一致，符合相同初始策略与随机条件下 Actor 不受私牌 Critic 输入影响的预期；参数差分显示所有 Actor 层均有更新。流程检查的每种对手仅 4 场，不能据此排名。正式小试验计划每组 4 周期、每周期 16 场，共 256 场训练；每两周期对规则和历史对手各评测 32 场。实际量与结果由第 11 节记录。

这组对照匹配初始权重、场数及优化设置，不保证相同候选数、决策数或计算量；实际开销需一起报告。不能把 D 与旧蒙特卡洛训练直接相比，便把差异都归因于明牌信息，因为优化算法也发生了变化。各周期接续本组权重，但重新初始化 Adam 优化器，不延续上一周期动量。

正式小试验完成后，扩大对照在 `asymmetric-next/` 完成：每组 8 周期、每周期 32 场，四组共 1,024 条整场训练轨迹。扩大试验重新使用共同初始化，避免把小试验选模的偏差混入四组起点；单次试验内部仍持续接续权重。新训练种子从 `61010104` 开始，开发评测从 `62100104` 开始，与小试验分开；这仍是开发实验，不是最终留出验收。

### 4.5 持续自对弈训练系统（已实现，尚无棋力结论）

本节描述已实现的训练基础设施及开发流程验证；新增缩小参数测试出现明确退步（第 7.8 节），尚无默认配置长期训练提高棋力的证据。操作说明见[持续训练指南](CONTINUOUS_TRAINING.md)。

**设计依据。**参考客户端按名次给单局升级分 ±1／±2／±3，P0 在 400 个测试局面上的最高候选分数位于 [−3.05, 4.00]，与该回报尺度一致；据此推断 P0 是对单局升级分做蒙特卡洛回归的动作价值网络（推断，未见原始训练日志）。持续系统因此沿用同一结构与同一回报尺度继续训练，而不是在冻结网络上叠加小头。此前的整场实验受限于每周期数十至数百场的同步采样，见第 7.5、7.6 节。

**算法。**网络与 P0 相同（$567\to512\times5\to1$，1,341,953 参数，全部可训练），从 `ai/policy.onnx` 初始化。每条被选中动作的样本以 int8 保存 567 维输入，并保存本局升级分 $u$（本队 +1～+3，对方取负）与整场结果 $m\in\{+1,0,-1\}$。训练拟合

$$
L(\theta)=\mathbb E\big[(Q_\theta(o_t,a_t)-G_t)^2\big]+\lambda\,\mathbb E\big[(Q_\theta(o_t,a_t)-Q_{\theta_0}(o_t,a_t))^2\big],\qquad
G_t=(1-w)\,u_t+3w\,m.
$$

默认 $w=0$、$\lambda=0$，即延续单局升级分目标；$w$ 不改变已采样数据，可另开运行比较。这仍是只在被采样动作上回归的深度蒙特卡洛方法，没有对未选候选施加约束，第 4.2 节所述的排序漂移风险依然存在，由门控而不是损失函数兜底。

**采样与对手。**$N$ 个采样进程（默认 6）各自顺序打完整比赛，每场开始时读取最新导出版本。对手按 0.5／0.3／0.2 的比例为四席自对弈、联赛池成员和原规则机器人；联赛成员按 PFSP 抽取，权重 $(1-\hat s)^2+0.02$，$\hat s$ 是最新模型对该成员的近期得分（指数遗忘，加一胜一负先验）。训练席位从 $\operatorname{softmax}(Q/0.02)$ 抽样（依据见下文的探索测量），对手席位贪心；自对弈记录四席，其他对局只记录本队两席。进还贡仍使用模拟器的固定程序。

**训练进程。**重放缓冲区保存最新 2,000,000 行；达到 100,000 行后开始训练，Adam、学习率 $10^{-5}$、batch 2048、梯度范数裁剪 1.0；累计训练行数不超过累计采样行数的 4 倍。每 10 分钟导出与网页相同输入输出的 ONNX，并保存优化器状态以便续跑。

**联赛与门控。**调度进程每 60 分钟把最新版本加入联赛池（上限 24 个，初始模型与历届冠军固定保留）。每个新快照与当前冠军在新种子上贪心对局，每个种子交换阵营各一场，平局记 0.5；以种子对平均得分做正态近似 SPRT（$\mu_0=0.5$，$\mu_1=0.53$，$\alpha=\beta=0.05$，100～1,000 对）。接受即更替冠军。SPRT 的方差取样本方差与 0.05 的较大者，避免几对全胜就被当成确定结论。门控不含网页风格、残局搜索与直接出完捷径，属于**开发筛选**；冠军进入网页仍须按第 5.3 节完成留出验收并由人工确认，系统不修改 `src/ai/models.mjs`。

**数据用途。**本报告已有的开发与留出种子均小于 $10^9$。持续采样的比赛种子从 $10^9$ 起，每个采样进程独占 $5\times10^7$ 个；探索测量从 $3.4\times10^9$ 起；门控从 $3.5\times10^9$ 起，每次独占 $10^5$ 个。每局发牌由比赛种子派生，不同比赛种子极少数情况下可能得到相同的单局发牌。

**锚点与协议维护（2026-11-04）。**新增锚点专用区间 $[3.6\times10^9,3.7\times10^9)$，门控限制在 $[3.5\times10^9,3.6\times10^9)$；每次检查分配 $10^5$ 大小的块，启动前持久化块序号，耗尽即停止。默认每 3 小时冻结最新模型，对初始 P0 贪心评测固定 150 个配对种子、300 场整场比赛，胜／平／负得分为 1／0.5／0。令每个种子两场平均得分为 $X_i\in[0,1]$，报告 $\bar X\pm\sqrt{\log(40)/(2n)}$ 截断到 [0,1] 的双侧 95% Hoeffding 区间；连续两次完整检查的上限低于 0.5 时停止。未完成检查不计为一次失败，并重置连续计数。该区间针对单次检查，不控制长期反复监控的整体误报概率；不同开发运行可重用开发种子，不能视为独立留出。

训练、模拟和编码源码按 LF 规范化后冻结 SHA-256，重启及运行期间检查源码是否变化；变化时停止并要求新运行目录。报告器读取真实状态、逐种子结果、冠军历史和指纹，只有两份文档允许在专用干净工作树检查后自动推送。训练权重留在忽略的 `work/`，不改变网页默认清单。累计运行时间不含暂停；新增长期任务的计划时长不算实际完成时长。

**已完成的验证。**

- 导出：`ai/policy.onnx` 载入 PyTorch 再导出，ONNX Runtime 输出与原文件逐位一致；PyTorch 前向与 ONNX 的最大误差 $6.4\times10^{-6}$。
- 单元测试：标签与真实比赛结算一致、int8 分片往返、PFSP 排序、SPRT 判定、重放环形缓冲、续跑不重复计数，以及一次真实参数更新后所有层都发生变化。
- 推理速度（本机 7800X3D，单线程，同一 P0 图）：浏览器 WASM 运行库约 1.0–1.2 万候选／秒，原生 `onnxruntime-node` 约 4.2–4.6 万候选／秒；单个采样进程打完整自对弈约 620–660 决策／秒，其中推理约占六成。
- 端到端冒烟：3 个采样进程、缩小的缓冲区和 2 分钟快照间隔，运行 12 分钟。完成 2,101 场整场比赛、0 场出错，记录 981,053 个决策，训练 1,867 步，6 次门控，到时限后所有进程正常退出并发布最终版本。采样合计约 1,430–1,610 决策／秒，训练约 2.6 步／秒（batch 2048）。该次运行仍使用当时的 ε=0.01 均匀探索；冒烟参数下有一次门控只用 4 对就判定接受，据此把 SPRT 方差下限提高到 0.05，默认最少 100 对。
- 探索代价：探索方与贪心对手均为 P0，种子 3,400,000,000 起 150 对、各 300 场，平局记 0.5。贪心对照平均得分 0.500；ε=0.01 均匀探索 0.422（0.8% 决策非贪心）；softmax T=0.02 为 0.517（10.3%）；T=0.05 为 0.357（19.1%）。据此把默认探索改为 softmax T=0.02。每组约 ±6 个百分点的不确定性，只用于选择默认值。
- 冒烟模型对初始模型：12 分钟后的 v000001867 与 P0 贪心对局，种子 3,505,000,000 起固定 150 对：126 胜、147 负、27 平，平均得分 0.465，正态近似 95% 区间 [0.419, 0.511]。与初始模型没有显著差别，点估计偏低；不能据此说训练有效或有害。

## 5. 实验协议与统计

### 5.1 主要与辅助指标

当前主指标为整场队伍胜率 $\hat p=N_{\mathrm{win}}/N_{\mathrm{all}}$，平局也进入分母，并单独报告。辅助指标包括双上、双下、孤立头游和头游之后的决策数；当前没有把它们替代主指标。

历史单把胜率是“头游所在队获胜”的比例。升级分是另一种收益量，不能把升级分均值或其置信区间标成胜率变化。Brier、AUC 和分类准确率衡量应牌预测任务，也不能替代任何比赛胜率。

### 5.2 配对与不确定性

每个独立种子重复两次并交换学习队的座位阵营，使用共同的起始发牌与后续随机发牌序列。策略分歧之后的级牌、进贡、比赛长度和局面可以不同；配对不意味着之后每一步仍处于同一状态。

以种子为统计单元，把该种子的两场胜负指标取均值 $z_i$。既有部分报告用 $\bar z\pm1.96s_z/\sqrt n$ 的正态近似区间；它在样本较少、方差退化或结果接近边界时不能给出可靠覆盖保证，尤其不能把零胜样本的零宽区间解释为“真实胜率确定为零”。

自动快照另外报告按种子聚类的保守 Hoeffding 区间：

$$
\left[\bar z-\sqrt{\frac{\log(2/\alpha)}{2n}},\;
\bar z+\sqrt{\frac{\log(2/\alpha)}{2n}}\right]\cap[0,1],\quad\alpha=0.05.
$$

该区间以种子簇之间可视为独立、实验协议固定为前提；不修复反复选模造成的选择偏差，也不说明对其他牌规、人类或其他对手的泛化。不同版本必须在相同种子上比较逐种子差值，而不是只比较两个独立区间是否重叠。

### 5.3 发布判据

模型选定后，使用此前没有参与训练或选择的新种子，对固定规则对手进行完整比赛验收；同时对历史对手检查退步，再做浏览器数值与实际游戏检查。报告点估计、平局数、种子簇数量和区间。

“开发点估计超过 80%”“独立验收点估计超过 80%”和“有充分统计证据支持总体胜率至少 80%”是三个不同结论。本文尚未完成新的整场独立验收，因此不宣布后两项。若要声称总体水平至少 80%，需预先约定单侧下界和样本设计，不能测试后临时换口径。

### 5.4 网页决策流程的整场评测

新增 [整场入口](../scripts/evaluate-table.mjs) 与 [共享决策模块](../src/ai/table-policy.mjs)。网页控制器和评测器调用相同的输入准备函数；浏览器 Worker 和 Node 评测器调用相同的决策函数，包括直接出完捷径、风格、公开近期习惯、应牌网络的条件调用与已证明残局优先。Node 使用已安装的 `onnxruntime-web`，不经过逐决策 Python JSON 通道，也没有引入新的推理依赖。

```bash
npm run eval:table -- --pairs=1000 --seed=73010104 --styles=balanced --opponent=rule
npm run eval:table -- --pairs=1000 --seed=73020104 --styles=aggressive,conservative,observant,adaptive --opponent=balanced
```

以上是可复现命令，不表示已经完成这些规模的评测。默认 `purpose` 为开发用途；这个入口不自动执行最终留出验收或替换模型。报告保存原始逐种子、逐阵营结果、胜／负／平、整场胜率、单局升级分均值、种子簇 Hoeffding 区间、模型 SHA、源码 SHA、运行库版本及耗时。源码按 UTF-8、LF 换行计算指纹，模型按原始字节计算，避免 Windows 换行转换混淆证据。

它仍使用现有模拟器的自动进还贡，不能代替真人操作、真实网络同步或浏览器数值检查。残局的毫秒预算受设备负载影响，接近的浮点分数也可能因运行环境而改变排序。每种风格的区间不带多重比较修正；默认数量和小样本结果都不能替代预先约定的性格非劣效检验。

本轮同时修复 `core/moves.js` 的普通顺子遗漏，影响提示和规则对手，未修改主策略的独立候选生成器。新规则对手应按报告中的源码指纹识别，与第 7.5、7.6 节旧工作树的基线区分；这些历史训练与测试不重新标成新协议成绩。四组训练在原工作树中按原协议完成，没有中途引入本轮规则对手改动。

### 7.11 GPU 接入后的初期流水线观测：约 32% 的采样增幅

在 GPU 主运行启动后实际测量一个 120 秒窗口，完成计数直接取各采样进程的状态差分；与 CPU 停机前最后 120 秒逐场日志相比，学习决策吞吐从 2,420.89／秒到 3,200.14／秒，比值约 1.322，增加约 32%。该 GPU 窗口的学习器状态差分为约 6.50 次更新／秒，窗口结束时其进程平均约 6.03 次／秒；旧 CPU 进程在停机时平均约 4.81 次／秒。学习器状态约每 10 秒刷新，短窗更新率是状态快照差分，并非逐次梯度更新时间戳。

这不是随机化、配对或等配置实验：采样进程从 6 个增加到 8 个，两个时段使用的模型版本、运行库与机器负载也不同，观测期间还有实现检查。每配置仅一段短窗，不能给出可靠的长期置信区间，不能将差异全部归因于显卡或宣称整条流水线快 10 倍。相较第 7.9 节的计算短测，实际收益明显受 CPU 牌局生成与候选推理限制；显卡经常等待新样本，不用重复训练同一批数据来伪造更高吞吐。该观测没有新的棋力对战结论，继续按既定门控与锚点监控训练。[原始观测](evaluation/gpu-pipeline-2026-11-04.json)包含两个时间窗口、计数、实际时长、配置及源码指纹。

## 8. 正确性证据与能力证据的边界

完整网络受保护候选已在浏览器 Worker 中对 48 个真实牌局位置、7,922 个候选核对原生与 WASM 推理：48 个位置的最大值动作一致，最大数值误差约 $6.11\times10^{-7}$，页面错误为零。这证明该检查点在这些位置的数值兼容，不证明胜率提高。

逐层冻结测试、参数差分、完整比赛终止标签、头游后记录、牌的归属与候选合法性测试各支持相应实现属性。它们不能证明人类水平、最优策略、整个动作空间形式化完备或跨设备毫无误差。

## 9. 局限与可检验的后续方向

当前尚存在以下限制：

- 五种性格的差异主要由共享价值网络之外的固定偏好产生；没有五套独立训练的人格网络。
- 主观察是固定长度统计表示，没有专门的循环网络或注意力网络学习完整长期出牌序列；公开习惯统计也没有变成可训练记忆。
- 整场终局回报稀疏，当前实验没有证明能可靠地把长期队友收益归因到某一次拆对、让牌或使用炸弹。
- 全网络约束只对采样动作输出起作用，仍会发生策略退步；增加参数量本身不保证更强。
- PPO 前四候选限制探索空间；全候选实验消除了这项限制，但仍依赖候选生成器与样本覆盖。
- 进还贡决策、风格偏好和部分网页结束捷径尚未联合训练；实验直接评分与线上完整决策管线必须分开验证。
- 规则机器人与固定历史对手池覆盖有限，反复在同一开发集选择可能过拟合。
- 原始预训练过程和完整训练缓冲区仍未公开；已公开的研究权重不能弥补这些材料缺口。
- 新 Critic 即使获得当前全牌，也只使用压缩后的公开观察，并非完整世界状态表示；它的预测仍会有误差，不能当作最优解标签。

下一步可比较序列编码、可学习的风格条件输入、更丰富的历史对手池，以及不依赖实际隐藏牌的公开信息推断。它们目前是**待检验假设**，不是已经实现或已经优于当前系统的能力。任何新方法都应有相同牌规、相同对手、匹配种子和独立留出的对照实验。

## 12. 结论

当前产品是共享价值网络、条件式应牌预测、固定风格偏好及公开确定性残局模块组成的混合系统，不是五个独立的大模型。现有数据证明了若干限定协议下的预测或单把收益改善，但**尚未证明完整网络训练提高了独立整场胜率，也尚未完成 80% 整场目标的独立验收**。后续结论必须随真实实验更新，不能由训练量、开发峰值或界面标签替代。
