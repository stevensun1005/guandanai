## 硬性约束

- **不改网页默认模型。** 不修改 `src/ai/models.mjs` 和 `ai/policy.onnx`，除非冠军已经通过第 5.3 节的整场留出验收，并且仓库所有者明确同意。
- **只报告实际完成的结果。** 正结果、负结果、退步和协议变化都写入 `docs/MODEL_STUDY.md`；开发集峰值不能写成验收；门控记录属于开发筛选。
- **五种电脑都要是最强。** 不加难度档位。任何改动不能让某种性格变弱。
- **直接提交并推送到 `main`，不开新分支。** 这是仓库所有者的要求。推送前运行 `npm test`、`npm run format:check`，以及相关的 Python 测试。
- **不要把大文件提交进 Git。** `work/` 已被忽略，训练产物留在那里。`ai/experiments/` 已有约 553 MB 检查点在 Git 里，不要再往里加；需要归档的权重放到 GitHub Release 附件，在 `docs/evaluation/model-artifacts.json` 里记录 SHA-256。
- **种子用途不能混。** 小于 1e9 的种子留给开发评测和留出验收；持续采样用 1e9 起，探索测量用 3.4e9 起，门控用 3.5e9 起（见 `scripts/continuous/lib.mjs`）。新增用途要另划区间并写进文档。

## 当前状态

### 已实现

`scripts/continuous/` 下：

| 文件               | 作用                                                                   |
| ------------------ | ---------------------------------------------------------------------- |
| `supervisor.mjs`   | 启动／重启采样和训练进程、汇总 PFSP 统计、定时快照、触发门控、停止规则 |
| `actor.mjs`        | 采样进程：打完整比赛，按 softmax 探索选牌，写 int8 样本分片            |
| `learner.py`       | 深度蒙特卡洛训练：重放缓冲区、回归单局升级分、定时导出 ONNX            |
| `gate.mjs`         | 新快照与冠军配对对局，SPRT 判定是否更替冠军                            |
| `value_net.py`     | P0 结构的读写和网页兼容导出                                            |
| `lib.mjs`          | 默认配置、样本格式、探索规则、PFSP、SPRT、种子区间                     |
| `status.mjs`       | 进度摘要                                                               |
| `explore-cost.mjs` | 测量某个探索规则在整场比赛中的代价                                     |

命令：`npm run train:continuous`、`npm run train:status`。测试：`node --test tests/continuous-training.test.mjs`、`python tests/continuous_learner_test.py`。

### 实测过的数字

全部来自本机（Ryzen 7 7800X3D，16 线程，32 GB，CPU）：

| 项目                           | 结果                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------ |
| 单线程推理，P0 图              | 浏览器 WASM 约 1.0–1.2 万候选/秒；原生 `onnxruntime-node` 约 4.2–4.6 万候选/秒 |
| 单个采样进程                   | 完整自对弈约 620–660 决策/秒，推理约占六成                                     |
| 3 个采样进程同时运行           | 合计约 1,430–1,610 决策/秒                                                     |
| 训练进程（4 线程，batch 2048） | 约 2.3 步/秒，约 4,800 行/秒                                                   |
| 门控                           | 16 场整场约 12–20 秒                                                           |
| 导出往返                       | 载入 `ai/policy.onnx` 再导出，ONNX 输出逐位一致                                |

探索规则代价（`explore-cost.mjs`，种子 3,400,000,000 起，150 对、300 场；探索方与贪心对手为同一个 P0；平局记 0.5）：

| 探索规则       | 平均得分 | 非贪心决策占比 |
| -------------- | -------: | -------------: |
| 贪心（对照）   |    0.500 |             0% |
| ε=0.01 均匀    |    0.422 |           0.8% |
| softmax T=0.02 |    0.517 |          10.3% |
| softmax T=0.05 |    0.357 |          19.1% |

据此把默认探索从 ε=0.01 改为 softmax T=0.02：探索量多一个数量级，而在这个样本量下看不出代价。这是开发测量，每组约 ±6 个百分点的不确定性，只用于选默认值。

端到端冒烟（3 个采样进程、缩小的参数，12 分钟）：2,101 场整场、0 场出错、981,053 个决策、训练 1,867 步、6 次门控，到时限后正常停机。冒烟结束的模型 v000001867 与初始 P0 贪心对局 150 对：126 胜、147 负、27 平，平均得分 0.465，95% 区间 [0.419, 0.511]，**没有显著差别，点估计偏低**。12 分钟的训练本来看不出效果，但长期运行时一定要盯住「对初始模型」这一项（第 1 步）。记录见 [docs/evaluation/continuous-smoke-2026-11-04.json](evaluation/continuous-smoke-2026-11-04.json)。

### 还没有的

- **没有任何棋力结论。** 系统还没长期运行过，不知道持续训练能不能变强。
- 门控只比网络本身（贪心），不含网页风格、残局搜索和直接出完捷径。
- 没有锁定的留出种子，也没有冠军验收脚本。
- 训练目标默认只用单局升级分，整场结果的权重 `targetMatchWeight` 默认 0。
- 损失只约束被采样的动作，没有对全部候选的约束。
- 门控是单进程，SPRT 用的是正态近似。

### 第 1 步：启动长期运行，接入报告

**目标**：让系统一直跑，结果自动进研究报告。

1. 用默认配置启动：`npm run train:continuous -- --run=work/continuous/main`。运行至少 24 小时。
2. 扩展 `scripts/update-model-study.py`：读取 `<run>/status.json`、`<run>/gate/*.json`、`<run>/champion/champion.json`，把以下内容写进第 11 节生成区和 `docs/evaluation/model-study-progress.json`：
   - 运行时长、采样场数、决策数、训练步数；
   - 每次门控的挑战者、冠军、对数、胜／负／平、LLR、结论；
   - 冠军更替历史和模型 SHA-256。
3. 在 `supervisor.mjs` 里加「锚点检查」：每隔几小时，用 `gate.mjs` 让最新版本和 `models/anchor.onnx`（初始 P0）贪心对局固定 150 对（`--settings='{"minPairs":150,"maxPairs":150}'`，种子另划区间），记录平均得分和区间。连续两次区间上限低于 0.5 时，自动停止并在 `events.jsonl` 写明原因。之后可以考虑调低学习率，或者把 `anchorWeight` 设为大于 0 再开新运行。
4. 在 `tests/model_study_test.py` 和 `tests/continuous-training.test.mjs` 里加对应测试。

**完成标准**：第 11 节能显示持续运行的门控记录和锚点检查；全部注明是开发集；测试通过。

### 第 2 步：锁定留出种子，写冠军验收脚本

**目标**：冠军能不能上网页，用一个固定流程判断。

1. 选一段从没用过的种子作为留出集，例如 `900000000` 起 2,000 个。在 `docs/evaluation/` 新建一个 JSON，记录区间、用途和提交时间；提交后不再改动。
2. 新建 `scripts/continuous/accept.mjs`，调用 `scripts/evaluate-table.mjs` 的同一套逻辑：
   - 冠军 vs 当前网页默认模型，配对种子、交换阵营，五种风格都跑；
   - 冠军 vs 规则机器人；
   - 输出逐种子结果、胜／负／平、按种子聚类的 Hoeffding 区间和 SHA-256。
3. 每次用过的留出种子要记录下来，同一段种子只能用于一次最终决策。

**完成标准**：脚本能对一个冠军文件跑完并产出报告；文档写明判定规则（事先定好的单侧下界）；没有修改网页模型。

### 第 3 步：门控并行化

**目标**：门控速度跟上快照频率。

- 门控进程开 K 个工作进程，按种子对分配，结果汇总后再做 SPRT；
- 注意 SPRT 的停止判断只能在汇总后做，不能由单个工作进程决定。

**完成标准**：4 个工作进程时门控吞吐至少提高 3 倍；结论和单进程时用同样种子、同样顺序得出的结论一致（写一个测试）。

### 第 4 步：整场目标（势函数塑形）

**目标**：从单局升级分过渡到整场胜率，同时不增加方差。

1. 用采样进程的 `results-*.jsonl` 和比赛历史，估计整场局面胜率表 $V(\text{双方级数}, \text{打 A 失败次数}, \text{当前打哪方的级})$，写成脚本，产出 JSON。
2. 在 `learner.py` 增加目标选项：每局奖励 $V(s') - V(s)$（基于势函数的塑形）。
3. 用同一初始模型、同样采样设置，各开一个运行目录比较 `targetMatchWeight=0`、`0.5` 和势函数版本，对比门控记录。

**完成标准**：三个运行都至少跑够同样的训练步数；结果（包括负结果）写进研究报告第 7 节；默认值只有在证据支持时才改。

### 第 5 步：对全部候选的约束

**目标**：避免第 4.2 节记录的「验证误差下降、实战退步」。

- 采样时为每个决策额外保存前 k 个候选（例如 k=8）的输入和锚点模型分数；
- 训练时对这些候选加相对锚点的 softmax KL 项；
- 注意存储量：每个候选 567 字节，k=8 时样本量约为现在的 9 倍，需要相应调小缓冲区或改格式。

**完成标准**：有开关，默认关闭；开和关两个运行的对比写进报告。

### 第 6 步：验收现有最强候选

**目标**：尽快让所有电脑变强。

- 目前最强的已有候选是 `ppo-mixed` 第 14 周期的小 Actor（扩大实验里四组全网络模型对它的胜率都低于 50%，见研究报告第 7.6 节）。
- 用第 2 步的验收脚本对它跑留出验收。它需要 PPO 配置（`--config`），参考 `scripts/evaluate-table.mjs` 的用法。

**完成标准**：验收报告写进研究报告；只有通过了才提议替换网页模型，并等仓库所有者确认。

### 第 7 步以后（按证据决定是否做）

- **种群训练（PBT）**：同时跑 2–3 个训练进程，不同学习率和温度，定期复制表现好的权重并扰动超参数。
- **对局时搜索**：关键局面抽样补全其他三家手牌，用模型模拟到局末；先在门控里比较，再考虑放进网页 Worker。
- **进还贡学习**：选项少，可以枚举后用模型评估，见改进意见第 7 节。
- **新特征**：最近 20 手出牌序列、进还贡信息、牌权归属。需要新网络结构，先用 P0 蒸馏，再继续训练。

## 已知问题与风险

| 问题                         | 位置                               | 说明                                                                           |
| ---------------------------- | ---------------------------------- | ------------------------------------------------------------------------------ |
| 门控只看网络本身             | `gate.mjs`                         | 冠军在网页完整流程里不一定更强，第 2 步的验收负责兜底                          |
| SPRT 是正态近似              | `lib.mjs` `sprt()`                 | 方差下限 0.05、至少 100 对；冒烟时用 4 对就接受过一次，所以不要调低 `minPairs` |
| 对局结果含探索               | `actors/results-*.jsonl`           | `npm run train:status` 里的胜率只用于监控，不是评测                            |
| 每个决策等权                 | `learner.py`                       | 长比赛贡献更多样本，研究报告第 4.2 节记录过同样的限制                          |
| 进还贡是固定程序             | `scripts/lib/match-simulation.mjs` | 训练和评测都用同一套规则程序                                                   |
| 训练环境与网页规则各一套流程 | `scripts/lib/simulation.mjs` 等    | 改规则时两边要一起改，见改进意见第 12 节                                       |
| 客人能看到四家手牌           | `src/game/session.js:55`           | 与训练无关的安全问题，仍未修复                                                 |
