# 电脑对手：选择、计算与验证

## 当前选择

大厅依次提供 Clint规则机器人、GuanZero 最近两代、danMCai 初始版和danMCai 最近两代门控冠军。默认使用danMCai 现任冠军，普通最新导出不能替代冠军。GuanZero 名称采用 `guanzero-adp-gpubatch-44752` 这样的连字符格式，danMCai 显示真实版本；具体版本以 [模型选择与发布](WEB_MODELS.md) 和清单为准。

Clint（`clint-rule`）是独立 `rules-v2` 规则策略，不加载 ONNX，也不叠加到神经网络分支。历史规则基线 `original` 与 Clint 不同，旧成绩保持原版本标签。

## 计算在哪里发生

单人局和房主浏览器负责电脑回合；加入者主要显示房主发来的结果。主要推理放在 Web Worker，通过单线程 WebAssembly 使用设备 CPU；无需训练用显卡。实际用到网络模型时才下载权重并初始化会话，后续复用。首次加载、候选数量和设备性能都会影响等待时间，手机尺寸验证不等于真实 iPad 性能保证。

网络路径：`web/src/ai/controller.js` → 合法候选与可见状态 → `web/src/ai/worker.mjs` → ONNX 候选评分与配置允许的收尾处理 → 控制器合法性校验 → 对局事件。Clint 则通过 `web/src/rule-bot/runtime.mjs` 调用独立规则策略。资源失败会显示重试入口，不静默更换策略。

网络基础输入为 513 维局面和 54 维动作；GuanZero 另有公开历史输入 `[1,5,216]`。选用模型的配置和完整 SHA 保存在清单，不能只改名称假装兼容另一种输入布局。进还贡使用独立规则阶段。

## 对手能看到什么

- 当前座位自己的手牌、公开出牌和过牌记录。
- 其他座位公开的剩余张数、级牌及策略支持的公开信息。

不会把其他各家的隐藏手牌传入策略。房主维护完整桌面状态与策略输入范围是两件事；当前网络层尚未实现按座位保密发牌。

## 开发评测与历史边界

GuanZero 开发对手为随机、原版规则、P0、Clint（rules-v2）与真实 danMCai 门控冠军；每类默认 250 对固定种子交换阵营，共 500 场完整比赛。冻结检出使用独立五对手补评，面板显示实际完成数／500 和冻结冠军版本；历史 200 场单独保留，模型、对手及协议指纹不一致不能拼接或续跑。[运行方式](../../ai/guanzero/README.md) · [研究证据](../../ai/research/MODEL_STUDY.md)。开发胜率、门控晋升和独立验收是不同结论。

下文保留历史风格、应牌网络和残局实验的复现说明与原始结果。五种风格已退出当前菜单，不能将它们当成当前的五个模型或把历史成绩用于新发布版本。

## 历史复现：风格与独立模型

两者需要分清：

- **出牌风格**：在同一个引擎上调整风险偏好、牌型保留和配合方式。
- **独立模型**：不同的网络或权重文件，必须有真实可加载的模型资源及单独验证。

1.7–1.13 版本曾提供五种风格，共用经过数值验证的强化学习主策略。观察型还可以使用一个独立训练的应牌小网络：

| 风格 | 当前行为                                                       |
| ---- | -------------------------------------------------------------- |
| 均衡 | 保持模型原有的最高分选择，综合处理不同局势                     |
| 激进 | 在评分接近时更愿意争先、出多张牌和动用炸弹                     |
| 稳健 | 在评分接近时保留炸弹、百搭和控制牌，关注队友领先               |
| 观察 | 结合公开回应频率、应牌网络、剩余张数和队友领先调整选择         |
| 融合 | 根据对手余牌、自己的收尾距离、队友领先与公开观察，融合三种偏好 |

风格只在与最佳模型评分相差不超过 0.055 的候选中选择。它不是随机出牌，也不代表不同风格都更强。过牌被当作一次选择记录，不会据此断言对方没有某种牌。

## 历史复现：近期习惯记忆

首局使用本局观察；从第二局起，观察与融合型结合最近四个结束局及当前局的公开回应。每往前一局乘以 0.6，近期选择有更大影响。它区分面对对手和让队友领出的情景，按牌型与张数分桶，避免把五张顺子、三带二和炸弹混在一起。

这些统计只影响主策略评分接近的选择，不作为“对方一定没有牌”的证明。当前比赛重新开始时记忆清空，不按昵称在不同房间之间追踪玩家。后台只收到聚合计数，过去各家没有打出的牌不进入统计。

两份网络的权重和输入维度保持不变：应牌预测仍用已经验证的当局 253 维特征，近期记忆用于风格偏好。对应代码为 `web/src/ai/habits.js`；棋力比较使用固定种子、交换双方的五局区组，把同组各局一起计算误差区间。

1.13.0 对观察型、融合型各做 600 组配对、6,000 局，比较同风格的旧式当局观察。每手仍只在 0.055 的评分边界内调整，均衡型不受影响。观察型胜率为 49.85%，每局配对升级分均值 −0.00933，95% 区间 [−0.02838, 0.00972]；融合型为 50.10%，均值 0.00633，区间 [−0.01080, 0.02346]。区间都包含零，不能认定谁更强。

记录显示近期统计实际参与了观察型 136,391 次、融合型 136,368 次决策，分别改变 261、160 次应牌网络介入前的接近候选偏好。它提供不同的观察行为，不改变默认电脑或把这些风格说成新训练的强化学习模型。[观察型结果](../../ai/research/evaluation/habits-observant-1.13.0.json) · [融合型结果](../../ai/research/evaluation/habits-adaptive-1.13.0.json)。

```bash
node ai/danMCai/evaluation/evaluate-habits.mjs --pairs=600 --block-rounds=5 --style=observant --seed=20410104 --output=ai/danMCai/data/generated/habits-observant-heldout
node ai/danMCai/evaluation/evaluate-habits.mjs --pairs=600 --block-rounds=5 --style=adaptive --seed=20420104 --output=ai/danMCai/data/generated/habits-adaptive-heldout
```

这里是同桌连续五个独立发牌局的习惯观察检查，级牌随机，不模拟跨局进还贡或整场打 A；它和浏览器的完整比赛检查有不同用途。

## 历史复现：独立应牌网络

`ai/danMCai/models/baseline/response.onnx` 是历史版本实际训练并部署过的 253 → 64 → 32 → 1 监督学习网络，使用自对弈中的对手出／过记录。它只在观察型已决定出牌后，为主策略评分接近的多种出法预测下一位对手的回应，不改变原有出／过决定，也不覆盖残局证明。无需每局预加载：真正需要比较时，Worker 才下载约 74 KB 的权重。

500 局留出预测检查中 Brier 为 0.15321，优于线性基线 0.16334；但 6,000 局对战的配对升级分区间仍包含零，因此不宣称胜率更高，当时均衡型为默认。完整数据、训练命令和边界见 [模型训练](../../ai/research/MODEL_TRAINING.md)。

## 历史复现：融合型如何变化

融合型不掷骰子选择性格，而是在同一局面中加权融合争先、保留与观察偏好。对手快走完或自己进入收尾时，更偏向争先；队友领出时，更重视留牌；公开记录逐渐积累后，提高观察部分的权重。所有信息仍来自自己的牌与公开记录，主策略 0.055 的候选边界不变。应牌网络的影响按观察部分权重缩放，原有出／过决定与残局证明仍受到保护。

1.8.0 使用当时 16 张的残局上限，对均衡型和观察型各做 600 组交换双方、1,200 局检查。融合型胜率分别为 50.33% 和 49.92%，配对升级分区间均包含零。它提供随局势变化的行为，不宣称是更强的新模型；两份已有网络仍共享在不同性格之间。

[对均衡结果](../../ai/research/evaluation/adaptive-balanced-1.8.0.json) · [对观察结果](../../ai/research/evaluation/adaptive-observant-1.8.0.json)。不同对手使用不同种子范围，不能横向把小幅分数差当作排名。

## 公开信息残局

当只剩两个不同队伍的玩家、总手牌不超过 24 张时，两位已出完者的全部牌都已经公开。用完整牌库减去自己的牌和公开出牌，恰好就是唯一剩下的对手手牌；这里不需要读取另一家的隐藏状态。

`web/src/ai/endgame.js` 用这些牌做精确的对抗搜索，处理过牌后的重新领出与已走完玩家的接风。它优先检查模型评分高的动作，只在证明某条路线能先走完时采用；如果不能证明、牌数不一致或预算用完，就继续使用学习策略。使用该历史管线的风格都遵守这条已证明路线。

节点预算为 40,000，时间预算约 80 ms，计算发生在 Web Worker，不在界面线程。这项改进针对最后两家的收尾与升级分：到这一阶段，头游所属队伍已经确定，因此不以胜率上涨作为目标。它没有修改或重新训练神经网络权重。

大厅按东南西北设置，开局转换为房主座位编号。加入的朋友只查看设置；电脑接管空位时沿用该座位配置。联机转为本机继续时同步旋转座位映射。

## 历史复现：开发者评估

```bash
python -m pip install -r ai/environment/requirements-models.txt
npm run eval:profiles -- --pairs=600 --seed=20261104
```

工具以 Python 子进程进行本机 CPU 推理，使用固定发牌和相同先手，交换受测双方；它不属于网站，不会开启推理服务。结果写到 `web/artifacts/validation/profiles`，包含胜率、配对升级分区间、与均衡的选择差异、过牌／炸弹变化和原始逐局结果。通过 `--seed` 留出未用于调整的牌局。

`eval:profiles` 比较基础风格评分层，不调用第二个应牌模型。当前双模型路径可用 `npm run eval:response -- --style=adaptive --opponent=balanced --pairs=600 --seed=20320104 --endgame-cards=16` 比较；支持均衡、激进、稳健、观察、融合对手，并让双方都使用精确残局。`--opponent=legacy-observant` 专指不用第二模型的观察型，便于复现 1.7.0 的条件模型检查。

残局增强可以单独比较：`npm run eval:profiles -- --styles=endgame --pairs=2000 --seed=20263104 --endgame-cards=16`。基线为未开启精确残局的均衡策略。

### v1.10.0：扩大到 24 张

保持 40,000 节点和约 80 ms 预算，把公开信息两家残局从总共 16 张扩大到 24 张。预算用完仍保留模型原选择，只有已证明的走完路线才覆盖。

在留出种子 `20360104` 开始的 2,000 组交换双方、4,000 局中，相比已经启用 16 张残局的旧版本，配对升级分合计增加 **77 分**；77 组改善，0 组下降。每组两局平均增加 **0.0385 分**，95% 区间 **[0.0301, 0.0469]**。这比较的是同一均衡策略的两个搜索范围，主模型权重未变化。

新增范围内共证明 839 次路线，其中 141 次改变了原价值网络的选择。浏览器核对 7 个新增局面，覆盖 17–24 张，并保留原来的 8 个残局检查。它仍针对头游确定后的升级分，不据此宣称整场比赛胜率上涨。

```bash
npm run eval:endgame -- --pairs=2000 --seed=20360104 --cards=24 --baseline=16
```

[留出结果](../../ai/research/evaluation/endgame-expanded-1.10.0.json)。本机 CPU 检查中搜索调用中位数约 0.35 ms、95 分位约 80.1 ms；这些包含未能证明的预算结束调用，不能当作所有手机的性能保证。浏览器计算仍发生在 Worker 中。

### v1.4.0 留出检查

当时的搜索上限为 16 张。未用于开发检查的种子从 `20263104` 开始，2,000 组交换双方，共 4,000 局。相对原均衡策略，配对升级分合计改善 **152 分**；152 组改善，0 组下降，其余一致。每组两局的平均改善为 **0.076 分**，95% 区间为 **[0.0644, 0.0876]**。双方胜局仍为各 2,000 局，符合这项功能只介入头游已经确定之后的设计。

结果与限制：只覆盖这些固定发牌的独立单局，不是整场打 A 的成绩；搜索预算和设备性能也会影响介入次数。数据见 [残局结果 JSON](../../ai/research/evaluation/endgame-1.4.0.json)。浏览器额外复现了 8 个实际记录的改选残局，并检查风格不会覆盖证明结果。

评估使用单局随机级牌，不包含跨局进还贡和整场打 A，因此不能把结果直接当作完整比赛胜率。生产网页仍完全在浏览器推理，不依赖 Python。

### v1.3.0 行为检查

固定种子 `20261104`，每种风格 600 组交换双方的发牌，共 3,600 局。数据见 [结果 JSON](../../ai/research/evaluation/profiles-1.3.0.json)。

| 风格 | 对均衡胜率 | 选择改变率 | 同一局面下的行为变化                 |
| ---- | ---------: | ---------: | ------------------------------------ |
| 激进 |     51.00% |      2.78% | 少过 730 次，多用炸弹 508 次         |
| 稳健 |     50.08% |      2.33% | 多过 626 次，少用炸弹 399 次         |
| 观察 |     50.25% |      0.93% | 结合公开回应，在较少的局面中调整选择 |

这些结果支持“行为有差异”，尚不足以支持“风格比均衡更强”：三种风格的配对升级分 95% 区间都包含零。因此均衡仍为默认，风格供玩家按偏好选择。

## 判断改进是否有效

使用固定发牌、交换双方、留出未参与调整的牌局。除胜率外，还记录升级分、出牌合法性、计算耗时和选择差异。

单次漂亮出牌不代表整体更强。没有稳定验证结果的候选策略不会替换默认引擎。性能优化与棋力提升也分别记录。
