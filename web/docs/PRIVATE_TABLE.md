# 房主本机明牌工具

这是一个房主本机工具，不是新增的模型版本或账户权限。满足所有者预留入口条件时，大厅只在本人界面显示独立开关，入局后可在选项中切换，默认每次新房间关闭。公开指南不公布具体触发昵称。单人局和加入者不启用此入口，即使加入者使用相同昵称也不启用。手机昵称保留最多八个字符，不再在窄屏截断名称。

入口不作为房间规则广播，对手界面不增加明牌开关、牌面窗口或模式提示。**公开网页的脚本可以被查看，昵称触发不是密码或身份认证，不能保证别人发现不了。** 原联机协议的主机权限及已有快照范围没有因此得到安全加固，不能把界面隐藏说成抗修改客户端的权限隔离。

## 本人、队友与对手

本人可在独立面板查看另外三家的实际余牌。大屏左侧展开，紧凑屏幕可折叠；小屏的明牌窗口与 Top 5 轮流展开，避免同时占满牌桌。

启用时，本人开启的出牌评价、本人超时托管，以及对家空位电脑使用**当前 danMCai 冠军的明牌推演**。普通出牌评价默认的 danMCai-reason 推理搜索（2026-11-09 起）此时不运行，评价标题显示冠军版本与「明牌推演」。对家若是真人，不替换其决策，不向其页面授予明牌功能。该本机模式会覆盖电脑队友原先选择的普通模型决策，界面面板明确说明使用冠军网络。两名对手继续使用各自所选的普通 Clint 或神经网络模型，输入仍是自身手牌、公开记录和张数；不把本队的完整牌面对象传给对手分支。若对手或对家方向选的是研究机器人 9001，明牌推演仍优先于搜索：对家电脑在明牌模式下按冠军明牌推演出牌；对手的搜索只收到自己的手牌和公开信息，从不读取明牌窗口或完整牌面。

关闭后，对家电脑恢复原先选择的普通模型，清理明牌窗口和当前评价快照。在途旧决策按现有取消机制丢弃，并重新处理当前电脑回合；不把已经过时的明牌结果作为关闭后的出牌。

## 推演方法与局限

**目标：按整局结果比较，不按眼前牌权。**现阶段以整局为准：一局打完后的最终名次和本队升级分（±1／±2／±3）。整场（先打过 A）是后续训练阶段的内容，推演不按整场换算。

完整牌面只传入独立的 `oracle` Worker 分支，步骤如下：

1. **选候选**：用冠军网络给本人的合法出法打分，保留最多八种不同方案，并补入未包含的过牌与直接出完方案。
2. **短推演（备用）**：每种方案至少推进四手，之后继续推进到本人出牌（本人出完则到对家），最多十二手，只在这个座位用冠军估值。它只在时间不够、某个方案没能推到本局结束时作为后备。
3. **推演到本局结束**：每种方案先按四家都选冠军网络最高分（能直接出完时优先出完）的打法推演到本局结束，记下本队真实升级分；时间允许时再按网络分数做 softmax 抽样（温度 0.03），轮流给每种方案多推演几次，每种最多 12 次。同一局面使用固定随机种子，结果可复现。
4. **合并结果**：一次推演的结果只有 ±1 至 ±3，起伏很大；开局时一次推到底需要较多时间，每种方案往往只能推演两三次。因此把冠军网络对这手牌整局结果的估计当作相当于 4 次推演的先验，与实际推演结果加权平均。推演次数少时以网络估计为主，残局推演次数多时以真实结果为主。

时间预算为 2,500 毫秒软上限：每种已评估方案至少完成一次推到本局结束的推演，之后的抽样在超时后停止；单次推演不会被中途打断，因此不是严格的时间上限。用户选中的合法出法若未进入候选，会单独用同样的方法补算。

Top 5 顶部显示「明牌推演至本局结束 · N 种出法 · 每种模拟 K 次」；每个方案下方显示贪心推演的前四手（不含方案本身）；第二名起显示与第一名的差值，单位约等于本局升级分。百分数按本回合候选的最高与最低值重新换算，差值才能说明两个选项实际是否接近。百分数和差值都不是胜率或正确概率。

**修正记录（2026-11-05）。**最初的实现固定推进四手后，由当时轮到的那一家估值。不同方案的终点落在不同座位，比较的是各家只看自己手牌时的最乐观估值，以本队领出结束的方案被系统性高估，推演因此偏向用炸弹抢回牌权，连队友控制的牌也会压。第一次修正改为同一座位估值；第二次改为推演到本局结束，并用网络估计稳定少量推演的结果。

**仍有的局限。**推演中其他三家按冠军网络的打法模拟，不一定等于真实对手；开局阶段每种方案的推演次数仍少，结果主要依赖网络估计。没有比赛证据证明这种模式的胜率更高。

这是**完整牌面驱动的有限神经网络推演**，不是专门训练出的全信息网络、完整极小极大搜索或最优解证明。用于后续动作的贪心模型不一定重现真实对手的策略，有限根候选和深度也可能漏掉好牌。没有独立比赛证据证明这种模式胜率更高。主机和辅助 Worker 仍在浏览器本机运行，不修改冻结训练、冠军权重或默认清单。

## 数据隔离

使用过明牌工具的当前游戏对象会被标记在本机 WeakSet 中，后续各把不加入云端牌谱上传队列；关闭工具不抹去标记，直到新的游戏对象开始。此前已经入队的普通牌谱照常重试，不删除已有云端记录。普通 Top 5 展示仍用 `assisted=true` 区分并排除默认未辅助人工样本。

这一隔离不向房间规则添加秘密开关，不新增云端协议字段，亦不把这些数据接入活跃训练。

浏览器验证使用两个真实 PeerJS 上下文与 `kind=test`，包含同名加入者不可启用、本队推演、对手普通分支、关闭恢复及构造结算探针的上传排除。构造结算不是实际完成牌局，不计入棋力或人类训练数据。实际结果与源码指纹以[主报告](../../ai/research/MODEL_STUDY.md)和机器证据为准。

续场也保留排除：使用明牌时立即标记本机保存的同一整场；即使本局未结束就关闭网页，之后主动继续这场也不恢复上传。标记写入失败会尽量移除可续场记录，避免把旧的未排除标记当成可采集。它仍不是身份认证，普通评价／对手分支不读取额外私牌。
