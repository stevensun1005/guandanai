探索规则代价（`explore-cost.mjs`，种子 3,400,000,000 起，150 对、300 场；探索方与贪心对手为同一个 P0；平局记 0.5）：

| 探索规则       | 平均得分 | 非贪心决策占比 |
| -------------- | -------: | -------------: |
| 贪心（对照）   |    0.500 |             0% |
| ε=0.01 均匀    |    0.422 |           0.8% |
| softmax T=0.02 |    0.517 |          10.3% |
| softmax T=0.05 |    0.357 |          19.1% |

据此把默认探索从 ε=0.01 改为 softmax T=0.02：探索量多一个数量级，而在这个样本量下看不出代价。这是开发测量，每组约 ±6 个百分点的不确定性，只用于选默认值。

端到端冒烟（3 个采样进程、缩小的参数，12 分钟）：2,101 场整场、0 场出错、981,053 个决策、训练 1,867 步、6 次门控，到时限后正常停机。冒烟结束的模型 v000001867 与初始 P0 贪心对局 150 对：126 胜、147 负、27 平，平均得分 0.465，95% 区间 [0.419, 0.511]，**没有显著差别，点估计偏低**。12 分钟的训练本来看不出效果，但长期运行时一定要盯住「对初始模型」这一项（第 1 步）。记录见 [ai/research/evaluation/continuous-smoke-2026-11-04.json](./evaluation/continuous-smoke-2026-11-04.json)。

**局域网采样机**：`npm run train:remote -- --run=<共享运行目录> --slots=8-13` 让同一局域网的另一台电脑只跑采样进程，样本写回主机运行目录，训练和门控仍在主机。启动器核对冻结代码指纹、防止槽冲突、断线重启；报告、状态命令和面板已改为统计全部采样槽。只做过同机模拟测试，详见[持续训练指南](./CONTINUOUS_TRAINING.md#局域网内另一台电脑一起采样)。注意：远程电脑必须检出与主机运行相同的提交，否则会被拒绝；`gpu-main` 冻结的源码文件不能改动，远程启动器本身不在冻结列表里。

**快速采样进程**：`fast-actor.mjs` 一个进程同时打 48 局，GPU（DirectML）批量推理放在独立线程，并缓存候选生成；同条件下 4 个进程约为标准进程的 2.07 倍（1,220 → 2,530 决策/秒），与原版的等价性已验证，详见[持续训练指南](./CONTINUOUS_TRAINING.md#快速采样进程gpu-批量推理)。调度器属于 `gpu-main` 冻结源码，目前只能用 `npm run train:remote -- --run=<运行目录> --slots=<槽> --actor=fast` 启动。**建议**：`gpu-main` 结束后，在新运行开始前给 `supervisor.mjs` 加一个配置项（例如 `actorImplementation: "fast"`），让调度器直接启动快速进程，再开新运行；不要在 `gpu-main` 运行期间修改冻结文件。若要往 `gpu-main` 中途加入快速进程，先征得用户同意，并在报告中作为协议变化记录。

#### D1：用 LSTM 编码出牌历史（优先）

- **DouZero 的做法**：最近 15 手出牌整理成 5×162 的矩阵，送入 `LSTM(162→128)`，取最后一步输出，与局面特征拼接后进入 6 层 MLP（`dense1`～`dense5` 为 512，`dense6` 输出 1 个值）。
- **本仓库现状**：参考客户端的 `_process_action_seq()` 与 `_action_seq_list2array()` 已把最近 20 手整理成 5×216（每行 4 家 × 54），但 `prepare()` 没有使用，P0 也没有这部分输入。研究报告第 9 节把缺少序列编码列为局限。
- **要做的**：
  1. 在 `web/src/ai/encoding.mjs` 旁新增序列编码（沿用参考客户端的 20 手、5×216 排法，过牌与出完的哨兵值与现有 `replay()` 一致），并用参考 Python 实现做逐值一致性测试。
  2. 新网络 = P0 的 MLP + LSTM 分支；LSTM 输出接入第一层的投影初始化为零，使初始输出与 P0 逐位一致（写测试证明）。
  3. 样本分片增加序列特征；`learner.py`、`value_net.py` 支持新结构；导出新的 ONNX 输入，网页 Worker 与 `evaluate-table` 暂不切换。
  4. 新运行目录从 P0 等价初始化开始，与不带 LSTM 的对照运行比较门控和锚点记录。
- **完成标准**：初始等价测试通过；两组运行跑够相同训练步数；锚点和门控结果（包括负结果）写进研究报告。

#### D2：明确比较「升级分目标」和「胜率目标」

- **DouZero 的做法**：`--objective` 可选 `adp`（平均分差，默认）、`wp`（胜率）和 `logadp`，两种主要目标都发布了预训练模型。
- **本仓库对应**：这里只类比目标类型，不等同于 DouZero 的原奖励定义。`targetMatchWeight=0` 拟合单局升级分；`targetMatchWeight=1` 拟合整场胜 +3、负 −3、平 0，中间值是混合。含平局时，后一目标对应胜 1／平 0.5／负 0 的得分变换，不等于单独最大化胜局数；评测仍同时报告纯胜率、平局率和得分。
- **要做的**：把第 4 步的对照扩成四组：`targetMatchWeight` 取 0、0.5、1，加上势函数版本。主指标是整场胜率，同时报告单局升级分。
- **完成标准**：四组用同一初始模型和同样采样设置，跑够相同训练步数；按整场胜率选默认值，证据不足时保持现有默认。

#### D3：预测其他三家手牌作为辅助任务（DouZero+ 的对手建模）

- **思路**：自对弈时其他三家的真实手牌已知，可以作为监督标签。在网络上加一个辅助输出，预测队友和两家对手各自剩余的 54 类牌计数（每类 0／1／2），与 Q 值一起训练；若采用 54×2 通道，可表示计数至少为 1／至少为 2，不要求猜测不可辨认的同面物理副本 ID。这是本项目待验证的标签设计，不是已核实的 DouZero+ 原标签格式。决策输入仍然只用本人手牌和公开信息。
- **额外用处**：预测出的手牌分布可以作为第 7 步「对局时搜索」抽样补全三家手牌的依据。
- **要做的**：采样时额外保存三家的真实剩余手牌（只用于训练标签，不进入决策输入，也不进入网页）；`learner.py` 加辅助损失和权重开关，默认关闭。
- **完成标准**：有单元测试证明标签不进入决策输入；开和关两组运行的锚点、门控结果写进报告；同时报告手牌预测的准确率，但不把预测准确率当成棋力。

#### D4：固定评测牌局与基线集合

- **DouZero 的做法**：`generate_eval_data.py` 生成 10,000 局固定牌局，`evaluate.py` 可以给每个座位指定任意 AI；基线包括随机、RLCard 规则机器人和用人类数据训练的监督模型。
- **要做的**：生成一份固定的掼蛋评测牌局清单，记录种子区间和 SHA-256，放进 `ai/research/evaluation/`；基线至少包括随机合法出牌、规则机器人和 P0。可以与第 2 步的留出验收一起设计，但开发评测牌局和留出牌局必须分开。
- **完成标准**：任意两个模型文件都能用同一份牌局清单对比，输出逐种子结果和区间。

#### D5：进还贡单独建模

- **来源边界**：上游 README 链接了叫牌演示，但本次核对的标准训练源码仅列三个出牌角色模型，没有据此确认独立叫牌网络的训练实现，故不把“另训叫牌网络”写成已核实的原版事实。
- **对应**：掼蛋的进贡、还贡选项很少，适合单独的小网络或逐个枚举后用模型评估（与第 7 步的「进还贡学习」合并做）。

| DouZero 的做法                                  | 不照搬的原因                                                                                                                                                |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |

### 按整局胜负改进出牌推荐（待检验计划）

现在的明牌推演只向前推 4 至 12 手，再用网络估值，仍可能高估“短期拿到牌权”。按所有者的最终目标，改进方向是：

1. **（已实现，2026-11-05）推演到本局结束**：在时间预算内把每个候选一直推到本局结束，用真实的名次和升级分（±1／±2／±3）比较，而不是在中途估值；推不完时才用网络估值，并在界面标明。
2. **（已实现，2026-11-05，并以网络估计作先验稳定少量推演）多次抽样，减少偶然**：后续动作不只用一条贪心路线，按网络分数抽样多条路线取平均，避免一条特殊路线决定推荐。
3. **整场价值（后续阶段）**：现阶段只按整局结果比较；等进入整场训练阶段，再按整场局面胜率表（第 4 步）把升级分换算成对整场胜负的影响。
4. **评价按胜负算**：验收时对比“推荐出法”与“过牌／其他出法”在完整对局中的胜率和升级分，不用“是否拿到牌权”评价推荐质量。

完成标准：同一批局面上，新旧推演的推荐与完整对局结果对比写进研究报告；没有证据前，不宣称推荐更强。
