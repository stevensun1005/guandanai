# 训练路线图：更像人、能解释、会配合、以整场为目标

**设计文档 · 2026-11-07 · 依据 main `c9e3a6c` 时的代码与证据**

本文回答所有者的问题："接下来怎样训练，才能让 AI 打得更像人、理解人类打牌逻辑、分析每一手牌的牌力、知道什么时候压牌什么时候过牌、怎么和队友配合、怎么根据对手出牌不让对手赢、以整场胜利为目标。"

本文**只有设计假设，没有新的训练或评测结果**。所有数字均引自[主报告](MODEL_STUDY.md)与 [evaluation](evaluation) 中已完成的记录；每一步的指标、停止规则和证伪条件都是预登记草案，执行前仍须按 [AGENTS.md](../../AGENTS.md) 单独登记协议、冻结源码与种子。本文不授权任何计算，不改变网页冠军 017、冻结运行、奖励定义或 2026-11-11 的研究截止。

路线来自一次多代理分析：六个只读子任务分别梳理观察编码、训练证据、真人数据、分析界面、GuanZero 与规则机器人、文献；六份独立提案各经"规则与可行性""科学有效性"两轮对抗评审；再综合为一份路线并做完整性复核。被评审否决的项目列在第九、十节，保留原因。

### 1.2 网络看不见什么

[编码实现](../../web/src/ai/encoding.mjs)的 513 维输入只有：己手、12 个结构标志、合并的未见牌、上家最后一手、队友最后一手、各家累计出牌、剩牌数、级牌。以下信息**未显式编码**：

- 牌权归属、连续过牌数、当前这轮的牌型与大小。多数情形可由"上家槽＋队友槽"推出；但当这两个槽都不是出牌（过牌，或已出完的 −1 哨兵）时，网络分不清"自己领出新一轮"与"跟 p+1 的牌"，且 p+1 这手的牌型大小不在向量里。该类别须按 lead／follow／out-sentinel 分层统计（第 1.3 步）。
- 进还贡牌、谁进给谁、抗贡（只进 389 维进贡专项，且该专项已禁用）。
- 整场进度（打 A 失败次数、局数）；仅实验性的 61 维 extras 含此 8 项，无已部署模型使用。
- 按座位归属的未见牌、队友牌型估计、对手习惯模型。

扩展输入只能走网页加载器已支持的 `extras` 53／61 或 `history` [1,5,216]；新增输出头不影响网页，只要 `values` 输出保留（[推理入口](../../web/src/ai/policy-inference.mjs)）。

### 1.3 仓库量不出"为什么"

- Top 5 的"差 X ≈ 本局升级分"只是界面提示，没有任何校准数据集、可靠性图或 Brier。
- 没有不完全信息下的反事实引擎；唯一推演工具是房主明牌工具，且四家都由冠军网络代打。
- 没有按手的压队友、送队友、接风、防守标签；配合只有双上／双下总量。
- 没有冠军 017 的独立整场（含进贡、打 A）评测；现有整场记录是 009 在网页策略下的结果。
- **真人牌谱为零**：D1 只有 `kind=test` 行；[真人出牌比较工具](tools/compare-human-moves.mjs)从未在真实数据上运行。Clint 网站自 `4e45b8a` 起向同一 D1 上传两名以上真人的牌谱（`appVersion` 前缀 `c1977`），实际数量尚未核对。

### 1.4 文献能给的

- 掼蛋里目前最强、且唯一有对人评测的配方是"DMC 蓝图之上做搜索"（OpenGuanDan 的 GS2，对人 42.5%；没有超人掼蛋智能体）。DanZero+ 的 top-k PPO 头也胜过其 DMC 基线，但本仓库第 7.2／7.5 节的小头实验只有 +2.5pp 单把提升。
- 2026 年一篇掼蛋论文否定了"冻结整场预测器做势函数奖励"，与[改进意见](IMPROVEMENT_PROPOSAL.md)第 4 节的设想相反。
- Maia 式拟人需要 10⁷ 量级真人对局，数据上封死；Overcooked 证明小数据行为克隆可以做**队友模型**，做策略则无证据。
- 隐藏层探针、校准、信念采样搜索在四人团队牌类上都没有直接证据，属于外推。

## 二、原则

1. 一手牌的好坏＝对本局最终名次（±1／±2／±3）的影响；整场只在阶段 3 进训练。
2. 牌权、过牌、炸弹、压队友、接风只做分析标签与解释文字，永不进奖励、损失、门控、验收，不单独作为推荐理由。
3. 不写手工战术规则；Clint 策略不进 danMCai、GuanZero、评分、候选、残局、训练，**也不进新联赛**（评审一致否决"Clint 当训练队友／对手"）。Clint 只做评测对手与评测队友。
4. 新自博弈教师＝main 可核验的门控冠军；搜索蒸馏（ExIt）不属于冠军续打，须登记新谱系：冠军 SHA → 搜索配置 SHA → 蒸馏导出。
5. 每个实验先预登记目的、起点权重、优化器、单变量、冻结 SHA、独立未用种子、预算、指标与区间、停止规则；只报实际完成局数；负结果照发。置信区间一律按牌副簇或整场簇计算，真人数据另按局、按人聚类。
6. 真人数据 `unverified_browser`，`assisted` 默认排除，按整场切分，不自动接入训练。D1 中牌友的私牌只做信念采样，不做明牌复盘；本人座位的明牌复盘也须先在 AGENTS 与[明牌工具说明](../../web/docs/PRIVATE_TABLE.md)中写明授权。
7. 网络值是相对动作值；任何"概率／预计升级分"必须来自独立拟合，绑定模型 SHA 与对手类别并在界面注明。80% 不是目标。
8. 算力：Windows 自动研究窗口 2026-11-11 16:45Z 停止新计算；Mac 目前没有任何授权窗口，本文所有 Mac 评测需所有者授权，且无梯度、固定截止、监听本机 STOP、保留 5 GiB；周三后任何 Windows 计算需新书面授权，并须先把 `research-deadline.mjs` 的硬编码截止参数化。
9. 每个代码步骤都包含 `npm test`、`npm run format:check`、`npm run build`、相关 Python 冒烟测试、文档同步（README、CHANGELOG、受影响指南）以及 Pages 冠军 SHA 不变的核对；时间估计已含这些。
10. 每次评测在协议中写明消耗的种子块，并用脚本在两台机器的忽略日志上审计无重叠；目前仓库没有通用审计脚本，只有各评测自带的 `seed-audit.json`，需先补一个。

## 三、六个目标分别靠什么

| 所有者目标           | 现在缺什么                  | 起作用的手段                                                                        |
| -------------------- | --------------------------- | ----------------------------------------------------------------------------------- |
| 1 更像人、懂人类逻辑 | 零真人数据                  | 先收真人牌谱做一致矩阵（评测）；≥400 局后训 BC 头。本窗口内只能得到"像所有者与牌友" |
| 2 分析每手牌力       | 只有静态 `handCost`，未验证 | 探针检查冠军隐藏层是否已编码牌力；校准 Q 差→实现升级分；复盘工具显示结果差±SE       |
| 3 何时压、何时过     | 当前牌型不在输入；无反事实  | 信念采样搜索给每个候选"打到局终的结局分布"；extras 53 维补上牌权、过牌数、当前牌型  |
| 4 队友配合           | 只有双上／双下总量          | 队友×对手网格评测；队友多样性联赛（周三后）；按手配合标签只做描述                   |
| 5 按对手出牌防守     | 无对手剩牌威胁模型          | 搜索里的似然加权信念（过牌是证据）；剥削臂；按对手类别分报结果                      |
| 6 整场胜利           | 目标仍是单局                | 先量化单局／整场分歧有多大，再决定是否开 match head；整场是后续阶段                 |

## 四、阶段 0：本周内，不需要训练窗口

### 0.1 整场分歧统计（零算力）

**执行后的修正（设计原文保留）**：第 48 节已完成 009 两组旧档案再分析。`draw` 牌规下“败场以对方自己的 A +2／+3 结束”的占比恒为 100%，下文 ≥20% 门槛是规则恒等式，不能触发阶段 3；本次不自行制定替代门槛。017 仍无该项独立整场结论。[实际结果及分母](evaluation/match-objective-divergence-20261107/results.json)。

- 文件：新 `ai/research/tools/match-objective-divergence.py`。
- 口径：该批记录是 **009 在网页策略下对 Clint／最新导出** 的结果，只是代理值；阶段 3 门槛（R_ownA ≥15% 或 ≥20% 的输场来自对方 A 的 −2／−3）须等 1.4 的 017 记录重算后再判。目标 4、5、6。

## 五、阶段 1（1–2 周）：Mac 短评测＋复盘工具

Mac 评测合计约 6–8 h CPU，需一次性授权。每项沿用 [independent-mac-final](evaluation/independent-mac-final-20261106) 的控制器模式：`protocol.json` 写硬截止，控制器监听本机 STOP，启动前验证停止行为；`research-deadline.mjs` 只保护 Windows 注册目录，不覆盖 Mac。

### 1.1 强制偏离配对＋决策轨迹＋校准（约 15 min）

- 先用 200 种子发布 top-2／top-5 差距分布；轨迹语料 6,000 对（冠军对 Clint／P0／自身／混合）按种子块切分；强制偏离 10,000 对：随机一次把冠军决策强制为第 k 名（差距 ≥0.1 过采样并记权重），同模型同种子打完，回归"实现 Δ"对"预测差"。
- 主估计在"第 2–5 名、差距 0.05–1.0"展示层，自博弈与 Clint 类别分报，附 Theil–Sen 与分桶均值；保序回归按阶段（27–20／19–10／9–1）拟合，输出绑定 SHA 的 `calibration.json`（≤50 KB），先只进复盘工具。`handCost` 差只有在控制预测差后仍有增量解释力（残差回归区间排除 0）才允许显示。
- 文件：新 `ai/danMCai/evaluation/evaluate-decision-trace.mjs`、`evaluate-deviation-pairs.mjs`、`ai/research/tools/summarize-deviation-pairs.py`、`fit-coach-calibration.py`；证据 `evaluation/coach-deviation-2026111x/`。

## 八、怎样验证

- **更像人**：唯一有效口径是未辅助真人决策上的一致矩阵（0.5／1.5），按局与按人聚类 bootstrap；与冠军一致 ≠ 像强手，只能说"像所有者与牌友"；本窗口内目标 1 只产出一致矩阵，不改变出牌；真人路线的强度上限是非劣性。
- **能解释**：1.1 的 β 与分桶均值证明数字有无结果依据；复盘工具的信念 Δ 在偏离位置上与实现 Δ 的分桶一致性；每条解释只允许"结果差±SE"做理由，标签只做描述。
- **配合**：1.2 的 gap(X,O) 与双下份额；阶段 2 的未见队友格；真人队友配合只能在 0.5 会话中描述性记录。
- **防守**：只用结果量验证——对各对手类别的签名升级分、对方 A 局 −2／−3 率（0.1／1.4）、剥削信号（1.6）、阶段 3 的对方 A 转化率；"过牌信息是否有用"用 0.3 中阶段 B（报 ESS）与均匀信念在 200 个争议位置上对全信息参照的一致率比较；"过牌后对手接风"之类的标签率只做描述。
- **整场**：1.4 基线与 3.1 的 ≥2,500 对整场比分；`aFail='draw'` 与桌规 `once`／`reset` 不互通。
