# 牌局复盘（命令行）

长期计划主线三"复盘工具（B）"的命令行版：读已结束的云端真人牌局（D1 记录，`trust=unverified_browser`），在可精确求解的尾段逐手告诉玩家"这手值多少、最优是什么、丢了几分、最优打法怎么走"。只读本地数据，**不上传任何内容，也不写入数据快照目录**；报告默认写到被忽略的 `ai/danMCai/workspace/review/`，不要提交。

## 用法

```bash
node ai/danMCai/review/review.mjs \
  --raw=ai/shared/data/human-games/<快照>/raw \
  [--seat=all|0|0,2] [--out=ai/danMCai/workspace/review] \
  [--max-cards=40] [--max-nodes=5000000] [--max-ms=30000] \
  [--pimc=8] [--pimc-cards=20] [--workers=4] [--rounds=round-…json,…] [--limit=n]

# 只重新生成报告
node ai/danMCai/review/report.mjs --in=ai/danMCai/workspace/review/review.json
```

`--raw` 可以是目录（读取其中的 `round-*.json`）或单个记录文件。输出 `review.json`（机器可读）、`review.md` 和 `review.html`（自包含，浅色／深色均可读）。每个工作进程以 `nice -n 10` 运行；数值参数和 `--seat` 不合法时直接报错退出，一个工作进程失败会停止其余进程。输出目录（含经符号链接解析后的真实路径）不得位于 `--raw` 目录或任何 `ai/shared/data` 之下。

资源：默认预算下同一局共享的求解器置换表可增长到数百万项（只在新一次求解开始且超过 300 万项时清空），单个工作进程峰值内存约 3 GB（实测 `ac9ece36:5`，尾段 29 手），`--workers=4` 约 12 GB。内存紧张时减少 `--workers`；降低 `--max-nodes` 会缩短尾段，结果与审计口径不再相同。

## 报告内容

- **尾段**：与[真人尾盘审计](../endgame/human-endgames.mjs)相同，从最后一手往回走，用同一个求解器逐个求解，遇到全桌超过 `--max-cards` 张或超出预算时停止。每局开头写明尾段从第几手、全桌剩几张开始，以及更早一手为什么不能求解。尾段只取决于求解器，与实际出法无关。
- **每个所选座位的决策**：桌面（要压的牌、各家张数）、自己的手牌（中文牌面，级牌红桃标"配"）、实际出牌及其精确值、局面值、全部最优出法（保持局面值的候选）、丢分 = 局面值 − 实际值，以及求解器主变：从该局面起每家都出第一个保持局面值的候选，直到本局结束。丢分的决策另给出事后公开的其他三家手牌和"实际这手之后双方最优续打"。
- **汇总**：各座位跨局的复盘决策数、丢分决策数和合计丢分；另有按玩家标识（记录里的匿名 ID 前 8 位）分组的同口径表，因为座位号按每局记录，不同比赛的同一座位可能是不同的人。每局概览给出尾段开始时的精确值与实际结果。合计只加正的丢分（候选生成器之外的出法即使优于候选也不抵扣）。

所有精确值都标为 **明牌事后最优（结束后四家牌已公开）**：按整局最终签名升级分（本队 ±1／±2／±3，被双下 −3）在四家牌全部可见时的双方最优值。这是事后上限，只看自己手牌的玩家不一定能做到；牌权、炸弹、接风等中间信号不参与评分。

## 估计（可选，`--pimc=K`）

对丢分且全桌 ≤ `--pimc-cards` 张的决策，从出牌者自己的视角重估：按公开信息（自己的牌、已出的牌、各家张数，以及该座位自己经手的进贡／还贡牌）均匀抽样 K 种其他三家的牌，每个世界里精确求解每个候选（[PIMC 标注](../endgame/pimc-actor.mjs) 的 `labelDecision`，同一种子再逐世界计数）。报告给出有几个世界这手也丢分：

- 每个／多数世界都丢分：按当时能看到的信息本可以看出；
- 没有世界丢分：只有看到全部手牌才能发现；
- 不超过一半的世界丢分：从公开信息较难判断。

若实际这手的估计平均值与最佳并列，报告写明"实际这手已是（并列）最佳"，不另列一个同值的出法。

这是**估计**：均匀抽样忽略对手出牌透露的信息，平均明牌值还会高估以后才知道的信息。估计只在单独标注的区块和表格中出现，从不计入精确丢分合计。抽样种子由记录 ID 和手序号的 SHA-256 确定，结果可复现。

## 边界

- 只覆盖尾段；更早的局面目前没有精确值，后续若加入，只能作为明确标注的"估计"。
- 只复盘单局（一局打完的升级分），不换算整场（先打过 A、打 A 失败等）。
- 记录来自浏览器上传，未做身份验证；`assisted`（出牌前看过数字预评）和非本人操作（电脑、超时托管）在每手上标出，但仍计入该座位的统计。
- 复盘不改变任何机器人、训练、门控或网页默认模型，也不是棋力验收；建议能否帮助本人在未辅助对局中少丢分需另行验证。
- 测试：`node --test ai/danMCai/tests/review.test.mjs`（用 `collectedRound` 固定牌局，与独立的 `solveEndgame` 核对最优集合和丢分，核对主变合法且结束于报告的值，以及座位选择）。

Windows工作器直接使用Node并设为BelowNormal优先级、隐藏进程窗口；POSIX继续使用`nice -n 10`。目录与软链接安全边界在两种平台均作回归验证。
